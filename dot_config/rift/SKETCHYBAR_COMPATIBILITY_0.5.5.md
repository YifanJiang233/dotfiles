# Rift v0.5.5 / SketchyBar compatibility

Date checked: 2026-09-02. Sources checked: exact upstream commits [46f5ba06781ac73d145780d2dbfe96516c8ccfb0](https://github.com/acsandmann/rift/commit/46f5ba06781ac73d145780d2dbfe96516c8ccfb0) and [b67cf2efc447174ca9e0cd10f558a224ed32b038 (v0.5.5)](https://github.com/acsandmann/rift/commit/b67cf2efc447174ca9e0cd10f558a224ed32b038), plus the checkout at /private/tmp/rift-055-investigation.ShDncV/upstream.

## Verdict

The current workspace and front-app modules are broadly compatible with Rift v0.5.5. The event names, CLI subscription form, JSON output shape, workspace indices, and window fields consumed by the modules all exist in the v0.5.5 contract.

There is one definite dead command path: [/Users/yifan/.config/sketchybar/plugins/rift_front_app.sh:38-41](</Users/yifan/.config/sketchybar/plugins/rift_front_app.sh:38>) invokes "rift-cli query layout \"$active_space_id\"" positionally. v0.5.5 defines the space selector as the long option --space-id; the positional form is rejected by Clap. This failure is non-fatal because the same plugin prefers .is_active == true from the space-scoped workspace query, but the layout query should be treated as incompatible.

There is also a startup race: Rift launches run_on_start commands before registering its Mach server, while the current subscription script exits on the first failed subscription. If that race loses, there is no retry in the current configuration; a later SketchyBar reload still performs an initial query, but does not recreate the Rift CLI subscriptions.

The configured workspace coverage is narrower than Rift's configured state: [/Users/yifan/.config/rift/config.toml:197-222](</Users/yifan/.config/rift/config.toml:197>) defines 12 workspaces, with `__scratchpad` at index 11, while both SketchyBar modules instantiate and update only indices 0 through 9. [/Users/yifan/.config/sketchybar/items/rift_workspaces.sh:3-13](</Users/yifan/.config/sketchybar/items/rift_workspaces.sh:3>), [/Users/yifan/.config/sketchybar/plugins/rift_workspaces.sh:3-5](</Users/yifan/.config/sketchybar/plugins/rift_workspaces.sh:3>) Rift v0.5.5 permits a configurable workspace count and zero-based workspace names/indices, so indices 10 and 11 are an integration omission, not an API incompatibility. [rift.default.toml](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/rift.default.toml#L254-L266), [rift.default.toml](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/rift.default.toml#L283-L294)

## Events, subscriptions, and environment

The current script subscribes to exactly workspace_changed, windows_changed, focused_window_changed, and window_title_changed. [/Users/yifan/.config/rift/sketchybar_events.sh:11-13](</Users/yifan/.config/rift/sketchybar_events.sh:11>) All four are valid v0.5.5 event kinds, and the CLI form is subscribe cli --event EVENT --command COMMAND [--args ARG]; the event JSON is appended as the final command argument. [events.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/crates/rift-protocol/src/events.rs#L7-L31), [rift-cli.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/bin/rift-cli.rs#L467-L478), [cli_exec.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/ipc/cli_exec.rs#L161-L175)

The callback intentionally ignores the appended JSON and uses only RIFT_EVENT_TYPE to trigger one debounced fresh query. [/Users/yifan/.config/rift/sketchybar_event.sh:13-20](</Users/yifan/.config/rift/sketchybar_event.sh:13>) That is sound for this design: the four v0.5.5 event payloads carry workspace/window context, while the actual labels and focus state are obtained from the query response. The v0.5.5 executor sets RIFT_EVENT_TYPE for all four, plus the relevant workspace/window variables and RIFT_EVENT_JSON. [cli_exec.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/ipc/cli_exec.rs#L40-L113)

Event semantics relevant to the bar:

- workspace_changed is emitted when a virtual workspace is activated, together with a workspace name and native space_id. [engine.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/layout_engine/engine.rs#L648-L659), [engine.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/layout_engine/engine.rs#L3115-L3129)
- windows_changed is emitted for active-workspace membership changes and contains the active workspace's window IDs. [engine.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/layout_engine/engine.rs#L3131-L3155)
- focused_window_changed is emitted only for a resolved focused window in an active space; the callback must query to obtain its title/app metadata. [reactor.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/actor/reactor.rs#L2492-L2514)
- window_title_changed is emitted only when the title actually differs and the window belongs to an active space. [reactor.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/actor/reactor.rs#L2457-L2489)

Rift deduplicates identical CLI subscriptions, so rerunning the current registration command does not add duplicate command/argument pairs. [subscriptions.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/ipc/subscriptions.rs#L137-L163) CLI subscriptions are held by the running Rift server rather than tied to a client Mach port; the current setup therefore persists for the Rift process lifetime. [subscriptions.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/ipc/subscriptions.rs#L25-L30)

## Startup and reload behavior

The current configuration places /Users/yifan/.config/rift/sketchybar_events.sh in run_on_start and enables hot_reload. [/Users/yifan/.config/rift/config.toml:70-77](</Users/yifan/.config/rift/config.toml:70>) In v0.5.5, startup commands are spawned before the Mach server is started: execute_startup_commands is called at startup, while run_mach_server is called later. [rift.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/bin/rift.rs#L142-L165), [rift.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/bin/rift.rs#L215-L228), [util.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/common/util.rs#L54-L97)

Consequences:

1. The four subscription calls can race the Mach server registration. The current script exits immediately on any failed call. [/Users/yifan/.config/rift/sketchybar_events.sh:8-13](</Users/yifan/.config/rift/sketchybar_events.sh:8>)
2. A successful registration is followed by an immediate callback repaint, and the SketchyBar item setup separately forces an initial workspace repaint. [/Users/yifan/.config/rift/sketchybar_events.sh:15-17](</Users/yifan/.config/rift/sketchybar_events.sh:15>), [/Users/yifan/.config/sketchybar/items/rift_workspaces.sh:16-18](</Users/yifan/.config/sketchybar/items/rift_workspaces.sh:16>)
3. Rift config hot reload watches and reapplies config changes, but v0.5.5 invokes run_on_start only from the process startup path; the reload watcher does not rerun those commands. [config_watcher.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/actor/config_watcher.rs#L84-L113), [rift.rs](https://github.com/acsandmann/rift/blob/b67cf2efc447174ca9e0cd10f558a224ed32b038/src/bin/rift.rs#L163-L164)
4. SketchyBar reloads its current module set and runs --update; the workspace plugin additionally uses RIFT_FORCE_UPDATE=1, while later identical snapshots are skipped. [/Users/yifan/.config/sketchybar/sketchybarrc:29-37](</Users/yifan/.config/sketchybar/sketchybarrc:29>), [/Users/yifan/.config/sketchybar/sketchybarrc:61-64](</Users/yifan/.config/sketchybar/sketchybarrc:61>), [/Users/yifan/.config/sketchybar/plugins/rift_workspaces.sh:83-88](</Users/yifan/.config/sketchybar/plugins/rift_workspaces.sh:83>)

## Recommended compatibility action

Change only the front-app layout invocation from:

    rift-cli query layout "$active_space_id"

to:

    rift-cli query layout --space-id "$active_space_id"

If the bar is intended to represent every configured workspace, extend `RIFT_WORKSPACE_INDICES` in [/Users/yifan/.config/sketchybar/items/rift_workspaces.sh](</Users/yifan/.config/sketchybar/items/rift_workspaces.sh:4>) and [/Users/yifan/.config/sketchybar/plugins/rift_workspaces.sh](</Users/yifan/.config/sketchybar/plugins/rift_workspaces.sh:5>) through index 11; otherwise the current bar intentionally exposes only 0–9.

The startup race should be considered a reliability issue for the current run_on_start arrangement. It does not indicate a v0.5.5 protocol mismatch; it is caused by the ordering of startup-command execution and Mach-server registration. No installed Rift binary, service, or live configuration was changed during this investigation. The only created file is this report.
